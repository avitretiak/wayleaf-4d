# State machines and ownership

This is an inventory of stateful flows, including those represented by flags, timers, and cached values rather than an enum. States in different rows are independent; do not collapse them into one global status. Source is authoritative for exact transitions and error handling.

| Flow | Owner and states | Transitions and invariants |
|---|---|---|
| Worker lifecycle | `src/runtime.rs`: starting, running (first packet sent), stopping; process exit | Startup validates config, registers D-Bus, loads layout, prepares capture when needed and enters external control. Stop wakes the scheduler; cleanup attempts to restore the previous effect. Temporary capture failures exit 75 for systemd retry; permanent failures exit normally with an error. |
| Service lifecycle and observation | `src/control.rs`: private `ControlStatus` enum (stopped, starting, running, stopping, error); `running` and `enabled` are separate observations | Run/Stop and monitor changes set transitional status; refresh reconciles worker D-Bus and systemd. Worker status strings are validated at the boundary, and control serializes the same status strings in D-Bus JSON. A revision rejects stale refresh snapshots. `running` can remain true in an error or transition; login enablement does not imply running. |
| Control operations | `src/control.rs`: idle, control busy, device busy | Settings, lifecycle, monitor, and device tasks are serialized by the two busy flags. Completion or thread-spawn failure releases the relevant flag; snapshots collected before a revision change are discarded. D-Bus method success can mean accepted, not completed. |
| Settings transaction | `Backend.qml`, `src/control.rs`, `src/runtime.rs`: clean, pending/debouncing, in flight, retry pending, confirmed, failed pending | QML displays edits immediately, batches by key and retains pending values on failure; it retries once and offers manual retry. It waits for control idle and verifies returned values. A generation prevents an older response from replacing newer edits. The control delegates live changes to the worker, or persists them while stopped; the worker validates and saves before publishing its new revision. |
| Monitor selection | `Backend.qml`, `src/control.rs`: selected, changing, stopped for change, saved/restarting, error | Pending settings are flushed first. A running service is stopped and restarted around the save; a standalone worker prevents a switch. Save failure attempts to restart the old service. Monitor discovery errors retain the previous list. |
| Device management | `Backend.qml`, `src/control.rs`: unpaired/paired, discovering, pairing, refreshing details, disconnecting, failed | Pair and forget require a stopped worker. Device details may be stale independently of pairing; failed refresh retains stale data. Disconnect waits for stop and removes saved credentials, with a warning if power-off fails. Discovery and pairing results use device busy state, separate from worker status. |
| Preview subscription and samples | `FullRepresentation.qml`, `Backend.qml`, `src/control.rs`, `src/runtime.rs`: disabled, enabling, ready, sample in flight | The popup enables previews only when expanded, running and not in 1D. Closing or changing mode disables and clears them; generation checks discard replies from an older subscription. At most one sample request is in flight. Control and worker separately gate access to sample data. |
| Popup Look selection | `FullRepresentation.qml`: inferred or saved preset, Custom, user-edited | Initial selection is inferred from settings and saved identity. Leaving Custom snapshots its values; choosing Custom restores them. Fine-tuning selects Custom. Brightness and strip alignment are independent of Look data. |
| Capture and mode | `src/runtime.rs`, `src/capture.rs`, `src/kms.rs`: no capture in 1D, capture prepared for 2D–4D, temporary/permanent failure | A worker configuration revision rebuilds zones and creates or drops capture on mode changes. Display loss and temporary helper failures cause retry through service exit; invalid selection/protocol failures do not. Layout IDs remain those returned by the device. |
| Sampling and black response | `src/sampling.rs`: normal, near-black confirmation, confirmed black/fading, black, recovery | Per-zone elapsed time, prior colors and packet values drive smoothing and hysteresis. Strict black can bypass the fade; mapping changes reset temporal zone history. A mode or settings change is not a device calibration. |
| Letterbox detection | `src/sampling/letterbox.rs`: full or accepted crop, candidate under observation | Repeated time-based evidence accepts a candidate; ambiguous/dark frames retain the accepted crop. Dimensions or reset discard previous detection state. |
| Frame scheduler | `src/runtime.rs`: waiting, due, processing, rescheduled, stopping | Deadlines advance without unbounded catch-up; stop and configuration revisions wake the wait. 1D uses its own interval, and settings changes recalculate scheduling. |
| Configuration persistence | `src/config.rs`: loaded/default, candidate validated, locked update, committed or rejected | Settings and credentials share a file but update independently under a lock, preserving unknown fields. Validation precedes atomic replacement; failed writes leave the prior file intact. Never expose populated config or tokens in diagnostics. |

When changing a flow, test both transition outcomes and cross-boundary races: stale asynchronous responses, stop during startup, settings while a worker is changing state, and recovery after failures. Tests must not issue hardware writes unless the user explicitly requests them.
